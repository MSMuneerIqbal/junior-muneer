## Steps
1. Confirm the requested date range; use the user's timezone. For the current week's app activity use what_happened with period=week. For other ranges use available history and state any gaps.
2. Read relevant recent_chats only if the report needs more context. Combine these facts with the user's own update, avoiding repeated retrieval.
3. Separate verified completed work, work still in progress, waiting approvals and blocked items. A draft is not a sent message; a prepared file action is not an executed change.
4. Suggest at most three priorities for the next week based on the user's goals. Ask about any important unresolved contradiction rather than guessing.

## Result
A concise review: completed, unfinished, blockers, next week. Include dates and links or file paths when the tools provide them. Say when the app's records may not cover work done elsewhere.

## Boundaries
Do not change tasks, send the review, create events or save memories merely because they appear in the report. Follow all permission and source rules for any separately requested actions.
